GUNSIGHT PLAYER CLASS ICON

Design reference, 2026-10-13, class icon on a player target, three concepts
The ask: when the target is a player, show their class icon. The box, level tag and ToT plate are drawn from the real code (GunsightTags.lua plate 15 tall, chamfer 5, pad 5, gap 3, Mononoki Bold 11; target box 134 x 64, chamfer 8, gunsight-target-wider-2026-10-09). Every scene is shown at 1x (one image px per screen px, the real size) and 3x. Three distinct ideas: A the glyph in the level tag's icon slot, B a round class medallion on the box corner, C a class spine plus class coloured name plus a glyph seated on the divider. Players are never elite, rare or boss, so for a player the level tag's classification icon slot is free; NPCs keep their level tag exactly as shipped (crown shown below).

00 FIXED FACTS USED BELOW

House style. The shipped level icons (tools/assets/generate_level_icons.py) are solid, chunky silhouettes filled white in alpha and tinted with SetVertexColor, 10 to 14 px, not thin line art. The nine class glyphs follow that: solid or heavy stroke shapes on a 12 x 12 grid, one tint, no inner detail finer than about 1 px. Class colours. The addon defines none (no RAID_CLASS_COLORS use in the source); these are the Blizzard Classic values, which the implementation should read from RAID_CLASS_COLORS at runtime rather than hard code. Box tone. Today the box edge is steel at rest, pink for a kickable cast, red only for INTERRUPTED; the red hostile box and steel friendly box in these scenes are illustrative of the ask, not shipped behaviour. The plates keep their pink outline as in code. Target in all scenes is out of cast (no KICK tag, no cast tile).

04 WHEN THE CLASS CANNOT BE READ (COMBAT, SECRET)

The same hostile player in all three concepts with the class unreadable. Rule for all three: draw nothing for the class, never a guessed or stale class. The level digits keep working exactly as today.
FactStatusNote
UnitIsPlayer("target")DOCUMENTEDBoolean. False for NPCs, pets and guardians, so they never get a class mark and keep the shipped level tag. If it reads as a secret value, treat as not a player: draw nothing.
UnitClass("target")DOCUMENTED, secret behaviour UNVERIFIEDReturns the localised name, the classFile token (WARRIOR ... DRUID) and a numeric id. Use the token. Whether it is a secret while in combat is not recorded anywhere in the repo, same open question as UnitClassification in the level tag mockup. Needs one in-game probe on a player target acquired in combat.
Secret pathRULECheck the token with FS.IsSecret before touching it. Secret, not a string, or not one of the nine: clear the mark (A: slot width 0, plate shrinks to digits; B: tile hidden, level tag back at dx 1; C: no spine, white name, divider unbroken). Never index a colour table with a secret key, never compare it.
Cache?OPTIONA player's class cannot change while targeted, so a class read out of combat at PLAYER_TARGET_CHANGED could be kept until the target changes. Clear it on every target change so a new unreadable target never inherits the last class. The mark is only ever absent or right.
