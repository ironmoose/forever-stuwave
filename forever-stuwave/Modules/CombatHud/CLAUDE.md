# CombatHud

The combat HUD: HudSpells -> HudProfiles -> HudLogic decide what to show, CombatHud and the Gunsight* files draw it.

## Patterns
- `HudLogic.lua`'s OnUpdate runs whenever a profile exists (Reconcile and Prune run with zero subscribers; only the state build is gated on subscribers). An unchanged tick's addon-side allocation should be zero: it builds into a reused scratch, reads each spell cooldown once, and compares a flat buffer. `hud-harness.py` measures it (`idle_tick_addon_side_allocation_*`), under LuaJIT with jit.off: indicative only, the client runs PUC 5.1 and still allocates its own API result tables.
- The target info box's rail heights, width and value numbers are `FS.Config` keys (`GunsightBoxes.SETTINGS`, shown in the config window). One slider px is `C.BAR_PX` image px (defaults 11 and 4); the width multiplier is `setting / 100 * C.BAR_WIDTH_SCALE`, and a width stored on the old scale is converted once per profile (`widthMigrated` flag); numbers go only to `SetFormattedText` (a secret one through `AbbreviateNumbers` first, never measured; a plain one fitted to its half of the row), percent through `UnitHealthPercent` / `UnitPowerPercent`. Fit a FontString's text with `GetUnboundedStringWidth`: `GetStringWidth` is bounded by the FontString's own width and always "fits".
- Target side seam: `GunsightAreas.lua` owns the dot piece frame and the upper and lower host frames; modules call `FS.GunsightAreas.RegisterModule(id, { build(host), seat(rect), onShow(area), onHide(area), classes })` for `debuffsH`, `debuffsV` or `class` (several `class` specs allowed, the one whose `classes` lists the player's token wins). `classSoon` (no `classes`) is the fallback for `class`: an area set to the Class Module shows it when the player's class has no class spec (a readable token that no spec lists), so a class that gains a module stops showing it with no other change; `AreaOf("class")` stays nil for the plate and `AreaOf("classSoon")` reports where it is; the plate itself is in `GunsightClass.lua`. A module is built on first use and may register before or after the areas build. `seat(rect)` gets the area's image px `{ x, y, w, h }` (one table, read only) on build, on a move between areas and on every rescale; `AreaOf(id)` is `"upper"`, `"lower"` or nil, and ignores the target gate. The Target Debuffs host follows `FS.TargetTakesDots`; a `class` module and the `classSoon` plate follow `FS.HasTarget` (both re-read in `ApplyHosts` on target events; `AreaOf` ignores the gate). With no target a class host hides and its `onHide` fires (`onShow` when a target returns), so the module stops its events and OnUpdate; no module may show with no target (a combo module also gates on a hostile target inside its own frame). Modules must stay plain frames: a secure button parented under a host makes it protected, and `ApplyHosts` and `SetParent` would be blocked in combat.
- Shaman Class Module: `GunsightShaman.lua` registers the `class` spec for SHAMAN and draws Concept A's four totem poles (mockups/gunsight-class-module-shaman-2026-10-08.html): 8 blocks of `ceil(remaining / duration * 8)` per pole, the head sinking on top, the last block amber, DROP / locked / FAR looks, a timer bar when a totem is up with no knowable number. All state comes from `ShamanTotems.lua` (`FS.ShamanTotems`: `Get(slot)`, `Blocks`, `Remaining`, `DurationObject`, `Subscribe`, `Tick`; Fire 1, Earth 2, Water 3, Air 4), which keeps listening while the module is hidden: out of combat `GetTotemInfo` is plain but haveTotem is true with a blank name for an empty slot (up = a name or a duration), in combat every return is secret and only the `GetTotemDuration` object (not nil) says a totem is up, numbers then come from the last plain read or from the drop stamped at `UNIT_SPELLCAST_SUCCEEDED` plus the base duration in `DEFS` (unmeasured values are marked there). FAR is set only from two plain `UnitPosition` reads (drop stamp vs now, same instance id) past the totem's range; verified live: pending probe. The shock trace and Fire Nova ring are `GunsightShamanShocks.lua`'s (no KICK tag there; KICK comes from `GunsightTape.lua`'s class neutral tag): the module calls `FS.GunsightShamanShocks` Build / Seat / OnShow / OnHide when that table exists, and tells the section where the Fire totem is through `section.SetFire(up, headY)` (`up` = the Fire totem stands and is not FAR, `headY` = the Fire head's centre in image px from the rect's top; called when either changed and once after the section's OnShow). A set drop (Call of the Elements, Ancestors, Spirits) stamps every element whose multi-cast slot for that set holds a spell (action id `(barIndex - 1) * 12 + (set - 1) * 4 + slot`, `HasAction` / `GetActionInfo` plain; numbers from `DEFS` through the assigned spell, plus the drop position), replacing a standing totem's numbers; an element with an empty set slot is untouched. When the bar index or `HasAction` is unavailable it falls back to stamping only the slots not up. The pole art that a solid texture cannot draw (block with its dark line, dashed mold, dashed DROP / FAR head outline) is baked by `tools/assets/generate_totem_pole.py`. The IMBUE and SHIELD chips are on the Shaman buff tab on the Console top edge (`Modules/ActionBars/BuffTab.lua`, data in `ShamanBuffs.lua`, always visible, no target needed). `gunsightshaman-harness.py` pins the poles, `shamantotems-harness.py` the data, `buffbar-harness.py` the tab.
- Which module each area holds is `gunsight.target.upper` / `.lower` (`Gunsight.GetArea` / `SetArea`). `SetArea` swaps with the other area when it already shows the picked module (Target Debuffs H and V are one family); `Gunsight.OnAreaChanged` fires once per `SetArea` (the swapped key included) and once per key for a profile switch or direct config write, so listeners must recompute from state.
- The Gunsight master switch (`gunsight.enabled`) applies live to what was built: `Gunsight.IsEnabled()` is the login snapshot (what exists), `IsActive()` / `OnActiveChanged(fn)` follow the switch, and the root (parent of every piece) is shown or hidden, by alpha only in combat with the real Show or Hide owed to PLAYER_REGEN_ENABLED. `GunsightTape.lua` listens and hands the casts to Stack A (`FS.CastBars.ClearView`) or takes them back (`SetView`); a new module that draws casts or owns a listener must do the same from `OnActiveChanged`. `NeedsReload()` names what cannot be live (a Gunsight never built, the classic combat HUD never drawn) for the config row. In combat the root only fades, so an insecure OnEnter, OnClick or tooltip under it must return early while `IsActive()` is false (the secure target of target button and the secure target menu button, both in `GunsightTags.lua`, are the accepted exceptions). A frame the Gunsight drives but that is not under the root (the party frames, via `ConsoleKeys.lua`) is stood down with `ReleasePiece(key)` while inactive and taken back with `ResumePiece(key)`; Console keys hide and the party piece releases from `OnActiveChanged`.
- Target menu: `GunsightTags.lua`'s second secure button (`FS.GunsightTags.menu`) covers the target box and opens the unit menu on a right click (`unit = target`, `*type2 = togglemenu`, `RightButtonUp` only; left and middle fall through via `SetPassThroughButtons`, read back with `ShouldButtonPassThrough`, else the mouse stays off and one line is logged). It hangs from the box ANCHOR with the box frame's offsets, never from the box frame (which moves in combat), is built and reseated out of combat only (`box.onGrow`, rescale, `PLAYER_REGEN_ENABLED`), and is hidden with no target by `RegisterUnitWatch`; never call Show or Hide on it. Accepted limits: (1) while there is a target, a right-button press that starts over the box opens the menu and does not start a camera turn (left and middle pass through; the right button is the menu); (2) like the master-off exception above and the target of target, the mouse cannot be switched in combat (`EnableMouse` on a secure frame is blocked), so turning the Target piece off mid fight leaves the invisible box taking right clicks until `PLAYER_REGEN_ENABLED`, and a piece turned on mid fight waits the same way.
- Player class badge: `GunsightTags.lua` draws Blizzard's round class icon (`Interface\\TargetingFrame\\UI-Classes-Circles`, cut by the global `CLASS_ICON_TCOORDS`) in a plain tone-framed tile on the target box's top left corner, for a player target only (`gunsight.tags.classicon`, default on); the level tag slides from dx 1 to 17 while it shows. `UnitIsPlayer` and `UnitClass` may be secret in combat: either one secret, missing or unknown draws no badge and leaves the level tag at dx 1. It is cleared on every target change, re-read next frame and at `PLAYER_REGEN_ENABLED`, takes no mouse (the secure target menu button under it keeps the clicks), and allocates nothing after the build.
- Shaman shocks lane: `GunsightShamanShocks.lua` (`FS.GunsightShamanShocks = { Build(frame), Seat(section, rect, scale), OnShow(section), OnHide(section) }`, loaded right before `GunsightShaman.lua`, which owns the module frame and the totem poles and calls it) draws the shock trace and bolt, and the Fire Nova ring (on its own frame above the Fire head, so the head's fill does not hide it) and NOVA tag. It draws no KICK tag and reads nothing from the target: KICK comes from `GunsightTape.lua`'s class neutral tag. READY is the plain `isActive` of the shared Earth / Flame / Frost Shock cooldown (a plain false is trusted, a plain isOnGCD or a cooldown no longer than the global one is ready); out of combat the label is the plain start and duration, in combat the seconds are secret and the label is a "~" estimate from the player's own casts (`UNIT_SPELLCAST_SUCCEEDED`, matched by spell NAME so any rank counts, a ledger that stays on through `OnHide`); the fill is the engine's (`C_Spell.GetSpellCooldownDuration` into `StatusBar:SetTimerDuration`, a plain number without that API); a secret `isActive` is "?" and guesses nothing. `GunsightShaman.lua` tells the ring where the Fire totem is through `section.SetFire(up, headY)` (a function on the section, not on the table; `up` true / false, `headY` the head's centre in image px from `rect.y`, 24 for a full pole, or `false` for a timer bar pole whose head rides the engine's fill: no ring, the NOVA tag stays): the ring and NOVA tag follow it, so the ring moves with the head as the pole drains and goes when the Fire totem is gone or FAR. Only if nobody has called it (`fireUp` nil) does an unusable Fire Nova (not for mana) read as no Fire totem. One 0.1 s OnUpdate runs only while a shock or Fire Nova counts down. Textures are baked by `tools/assets/generate_shaman_shocks.py`; `gunsightshamanshocks-harness.py` pins it.
- Shaman pole click: `GunsightShamanDrop.lua` (loaded right after `GunsightShaman.lua`) puts one SECURE catcher over each open pole column (image px from the module origin, `Shaman.Origin()`, reseated from `Shaman.OnSeat(fn)`; from `GY - NB * BP - HEAD_H - CROWN_UP - 8` down to `GY + LABEL_Y + 4`), so a left click casts what that element's totem tab button casts, a re-drop when the totem already stands. It is the one deliberate exception to "everything hangs under the host": the poles are plain, so the catchers hang from `Gunsight.root` through a `SecureUnitButtonTemplate` holder that carries `unit = "target"` and `RegisterUnitWatch` (the engine's own `[@target,exists] show; hide`, in and out of combat; state drivers and snippets do not run on this client). A catcher is a real `SecureActionButtonTemplate` with a COPY of the tab button's `type1` / `action1` / `spell1` (empty alt forms; never a `unit`), made when `TotemBar.OnAttributes(fn)` announces a settle, because `type = "click"` + `clickbutton` calls `delegate:Click(button)` with `down = false` and `SecureActionButton_OnClick` ignores that while the ActionButtonUseKeyDown CVar is on. The tab's buttons are read, never written. Mouse on (out of combat only; a change in combat waits for `PLAYER_REGEN_ENABLED`) while `Areas.AreaOf("class")`, `Gunsight.IsActive()`, `ShamanTotems.IsUnlocked(slot)` and a castable tab button all hold; right and middle clicks pass through where the client allows. Accepted limits as the target menu's: an area move, a reassigned area, or the dot piece or the master switch turned off, in combat leaves the catchers as they were, mouse on included, until regen (`EnableMouse` on a secure frame is refused in combat), so a left click on the invisible column still casts meanwhile; an element learned in combat only delays building its catcher until regen (nothing stale); on a client without `SetPassThroughButtons` the catchers keep the mouse anyway (the left click is the feature), one chat line says so, and a right-drag camera turn that starts over a pole is swallowed. An `Apply` that throws is logged once and retried at regen. `gunsightshamandrop-harness.py` pins it.
- Tooltips: an icon that shows a spell gets `FS.FrameHelpers.AttachSpellTooltip` at build plus `SetTipSpell` on paint (hover only, with an `opts.gate` that is false while `Gunsight.IsActive()` is false). The id and name are cached on the frame, so in combat the spell still shows; a secret id falls back to the name.
- `Hud.GetState()` always returns a fresh, caller-owned state. Only `Hud.Tick` builds in the scratch.
- Target debuffs: `TargetDebuffs.lua` (`FS.TargetDebuffs`: `Subscribe(fn(list, epoch))`, `Unsubscribe`, `Get`) is the only data source for the `debuffsH` and `debuffsV` modules in `GunsightDots.lua`. It reads auras only while `FS.AurasReadable()`, keeps a cast ledger in combat (an estimate, see its header), and takes Priest and Warlock rows from the Hud DoT ledger. An entry with `expires == nil` has no known duration (H shows "?" and no bar track, V skips it; a cast is timed from a snapshot of that spell id or name, else `SPELL_SECONDS` in TargetDebuffs.lua (Warrior filled), else HudSpells); `expires <= GetTime()` is absent, drawn only in combat.

## New Gunsight module: show/hide checklist
Everything on the target side hides with no target (player, live, Shaman: an IMBUE chip floated alone with no target; self buff reminders belong on the player side, not here). Before a module is done:
- Name its visibility contract: target (hides with no target, the default for `class`), dots (`FS.TargetTakesDots`), or always (only the player side, never the target side).
- A `class` module needs no gating code of its own; do not add a `showWithoutTarget` style exception without the player's recorded approval.
- Every frame, texture and font string hangs under the host the registry hands `build(host)`, never `UIParent` or `Gunsight.root`, so the host's hide takes it along.
- `onHide` stops the OnUpdate and every event the module registered; `onShow` restarts them and re-reads state (the spellbook, auras and weapons may have changed while hidden).
- Anything that happens while hidden and cannot be re-read later (a cast, a learned id) needs a listener that stays on through `onHide` and only records data (a Shaman imbue cast with no target is the example; that data model now lives in `ShamanBuffs.lua` because a self buff reminder belongs on the player side); everything else is re-read in `onShow`.
- `onShow` runs inside the `PLAYER_TARGET_CHANGED` dispatch, before per-target reads (combo points, `UnitPower`) reflect the new target: re-read them next frame (`RereadNextFrame` in `GunsightClass.lua`).
- A caller that draws something else while the module is on screen asks `AreaOf(id, true)` (nil while the target gate hides the host), and re-renders from `OnAreaChanged`, which also fires on the gate edge (CombatHud's Warlock shard count under the cast bar). The callback gets `reason`: `"gate"` when only a class host's target gate flipped, nil otherwise (registration, assignment, profile switch); a listener that only cares about assignments skips `"gate"` (TargetDebuffs does, and CombatHud skips it unless the player is a Warlock).
- Plain frames only (no secure button under a host), so show, hide and `SetParent` stay legal in combat.
- Walk these states: no target, dead target, friendly target, hostile target, in combat, after `/reload` with no target, the Console key off, and the Gunsight HUD off in `/fsconfig` (`IsActive()` false). The master switch hides the root and does NOT fire `onHide`: a module keeps its events while the root is hidden, so it must stay cheap and must not draw outside the root.
- The harness has a case that clears the target and asserts the host and module are not visible and `onHide` fired, then sets one and asserts `onShow` (see `gunsightareas-harness.py`, `a_class_module_hides_with_no_target_and_follows_it_with_its_hooks`; a module's own harness adds a real-areas case like `gunsightshaman-harness.py`).
