# CombatHud

The combat HUD: HudSpells -> HudProfiles -> HudLogic decide what to show, CombatHud and the Gunsight* files draw it.

## Patterns
- `HudLogic.lua`'s OnUpdate runs whenever a profile exists (Reconcile and Prune run with zero subscribers; only the state build is gated on subscribers). An unchanged tick's addon-side allocation should be zero: it builds into a reused scratch, reads each spell cooldown once, and compares a flat buffer. `hud-harness.py` measures it (`idle_tick_addon_side_allocation_*`), under LuaJIT with jit.off: indicative only, the client runs PUC 5.1 and still allocates its own API result tables.
- The target info box's rail heights, width and value numbers are `FS.Config` keys (`GunsightBoxes.SETTINGS`, shown in the config window). One slider px is `C.BAR_PX` image px (defaults 11 and 4); the width multiplier is `setting / 100 * C.BAR_WIDTH_SCALE`, and a width stored on the old scale is converted once per profile (`widthMigrated` flag); numbers go only to `SetFormattedText`, percent through `UnitHealthPercent` / `UnitPowerPercent`.
- Target side seam: `GunsightAreas.lua` owns the dot piece frame and the upper and lower host frames; modules call `FS.GunsightAreas.RegisterModule(id, { build(host), seat(rect), onShow(area), onHide(area), classes })` for `debuffsH`, `debuffsV` or `class` (several `class` specs allowed, the one whose `classes` lists the player's token wins). `classSoon` (no `classes`) is the fallback for `class`: an area set to the Class Module shows it when the player's class has no class spec (a readable token that no spec lists), so a class that gains a module stops showing it with no other change; `AreaOf("class")` stays nil for the plate and `AreaOf("classSoon")` reports where it is; the plate itself is in `GunsightClass.lua`. A module is built on first use and may register before or after the areas build. `seat(rect)` gets the area's image px `{ x, y, w, h }` (one table, read only) on build, on a move between areas and on every rescale; `AreaOf(id)` is `"upper"`, `"lower"` or nil, and ignores the target gate. Only the Target Debuffs host follows `FS.TargetTakesDots`; the class host is never target-gated (a combo module gates itself). Modules must stay plain frames: a secure button parented under a host makes it protected, and `ApplyHosts` and `SetParent` would be blocked in combat.
- Which module each area holds is `gunsight.target.upper` / `.lower` (`Gunsight.GetArea` / `SetArea`). `SetArea` swaps with the other area when it already shows the picked module (Target Debuffs H and V are one family); `Gunsight.OnAreaChanged` fires once per `SetArea` (the swapped key included) and once per key for a profile switch or direct config write, so listeners must recompute from state.
- `Hud.GetState()` always returns a fresh, caller-owned state. Only `Hud.Tick` builds in the scratch.
- Target debuffs: `TargetDebuffs.lua` (`FS.TargetDebuffs`: `Subscribe(fn(list, epoch))`, `Unsubscribe`, `Get`) is the only data source for the `debuffsH` and `debuffsV` modules in `GunsightDots.lua`. It reads auras only while `FS.AurasReadable()`, keeps a cast ledger in combat (an estimate, see its header), and takes Priest and Warlock rows from the Hud DoT ledger. An entry with `expires == nil` has no known duration (H shows "--", V skips it); `expires <= GetTime()` is absent, drawn only in combat.

## Dependencies
- Depends on: `FS.HudSpells`, `FS.HudProfiles`, `FS.Config` (GunsightBoxes, Gunsight areas)
- Depended on by: CombatHud.lua, GunsightSeals.lua (also `GetJudgement` and `GetSeals`), GunsightDots.lua, GunsightFrame.lua
