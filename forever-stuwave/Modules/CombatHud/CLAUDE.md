# CombatHud

The combat HUD: HudSpells -> HudProfiles -> HudLogic decide what to show, CombatHud and the Gunsight* files draw it.

## Patterns
- `HudLogic.lua`'s OnUpdate runs whenever a profile exists (Reconcile and Prune run with zero subscribers; only the state build is gated on subscribers). An unchanged tick's addon-side allocation should be zero: it builds into a reused scratch, reads each spell cooldown once, and compares a flat buffer. `hud-harness.py` measures it (`idle_tick_addon_side_allocation_*`), under LuaJIT with jit.off: indicative only, the client runs PUC 5.1 and still allocates its own API result tables.
- The target info box's rail heights, width and value numbers are `FS.Config` keys (`GunsightBoxes.SETTINGS`, shown in the config window). One slider px is `C.BAR_PX` image px (defaults 11 and 4); the width multiplier is `setting / 100 * C.BAR_WIDTH_SCALE`, and a width stored on the old scale is converted once per profile (`widthMigrated` flag); numbers go only to `SetFormattedText` (a secret one through `AbbreviateNumbers` first, never measured; a plain one fitted to its half of the row), percent through `UnitHealthPercent` / `UnitPowerPercent`. Fit a FontString's text with `GetUnboundedStringWidth`: `GetStringWidth` is bounded by the FontString's own width and always "fits".
- Target side seam: `GunsightAreas.lua` owns the dot piece frame and the upper and lower host frames; modules call `FS.GunsightAreas.RegisterModule(id, { build(host), seat(rect), onShow(area), onHide(area), classes })` for `debuffsH`, `debuffsV` or `class` (several `class` specs allowed, the one whose `classes` lists the player's token wins). `classSoon` (no `classes`) is the fallback for `class`: an area set to the Class Module shows it when the player's class has no class spec (a readable token that no spec lists), so a class that gains a module stops showing it with no other change; `AreaOf("class")` stays nil for the plate and `AreaOf("classSoon")` reports where it is; the plate itself is in `GunsightClass.lua`. A module is built on first use and may register before or after the areas build. `seat(rect)` gets the area's image px `{ x, y, w, h }` (one table, read only) on build, on a move between areas and on every rescale; `AreaOf(id)` is `"upper"`, `"lower"` or nil, and ignores the target gate. The Target Debuffs host follows `FS.TargetTakesDots`; a `class` module and the `classSoon` plate follow `FS.HasTarget` (both re-read in `ApplyHosts` on target events; `AreaOf` ignores the gate). With no target a class host hides and its `onHide` fires (`onShow` when a target returns), so the module stops its events and OnUpdate; no module may show with no target (a combo module also gates on a hostile target inside its own frame). Modules must stay plain frames: a secure button parented under a host makes it protected, and `ApplyHosts` and `SetParent` would be blocked in combat. Backing plate: each host carries one dark panel behind whatever it holds (`Areas.Plate(area)`; the party frame box recipe from `PartyFrames` `BuildRowBox`: `Theme.AddRoundedFill` in COLOR_BG at chamfer 6, then `Theme.SkinButton` with chamfer 6, `glowAlpha` 0.5 and the cyan `COLOR_POWER` border, so the ring and glow match the party boxes), the host's own child at the host's frame level so it sits below every module frame, with the fill, ring and glow all textures of the plate frame itself (no child frame at host + 1, or the ring and glow would draw over module art; `SkinButton`'s glow is seated on the plate by `Theme.RegisterGlow`, anchored to its corners, so `SeatHost`'s resize, a hide or show and a rescale carry it), sized to the area rect plus `Areas.PLATE_PAD` (3 image px; the areas are 4 apart) and shown only while a real `class` module is the occupant (not `classSoon`, which has its own look, not Target Debuffs), so the host's hide (no target, dot piece off) takes it along. Its opacity is `Areas.SETTINGS.background` (`gunsight.classModule.background`, 0 to 100 percent in steps of 5, default 80; the plate frame's alpha over a solid COLOR_BG fill, 0 hides it), applied from `Refresh` and `Config.OnChange`, never from `ApplyHosts`. A module needs nothing for it; the Gunsight HUD config page shows the slider under Target side. A harness that loads the real `GunsightAreas.lua` needs `Theme.AddRoundedFill`, `Theme.SkinButton`, `COLOR_BG` and `COLOR_POWER` in its Theme stub, or the missing helper is logged and there is no plate (`gunsightdots-harness.py`'s shared `stubTheme_` has them; its `SkinButton` enforces the chip rules only for a call that leaves the chamfer to the height, and records a plate's pinned-chamfer call in `PLATE_SKIN_CALLS`). `gunsightareas-harness.py` also loads the real `Theme.lua` for the glow registration case.
- Shaman Class Module: `GunsightShaman.lua` registers the `class` spec for SHAMAN and draws Concept A's four totem poles (the design mockup): 8 blocks of `ceil(remaining / duration * 8)` per pole, the head sinking on top, the last block amber, DROP / locked / FAR looks, a timer bar when a totem is up with no knowable number. All state comes from `ShamanTotems.lua` (`FS.ShamanTotems`: `Get(slot)`, `Blocks`, `Remaining`, `DurationObject`, `Subscribe`, `Tick`; Fire 1, Earth 2, Water 3, Air 4), which keeps listening while the module is hidden: out of combat `GetTotemInfo` is plain but haveTotem is true with a blank name for an empty slot (up = a name or a duration), in combat every return is secret and only the `GetTotemDuration` object (not nil) says a totem is up, numbers then come from the last plain read or from the drop stamped at `UNIT_SPELLCAST_SUCCEEDED` plus the base duration in `DEFS` (unmeasured values are marked there). FAR is set only from two plain `UnitPosition` reads (drop stamp vs now, same instance id) past the totem's range; verified live: pending probe. The shock disc and the Fire Nova flame disc are `GunsightShamanShocks.lua`'s (no KICK tag there; KICK comes from `GunsightTape.lua`'s class neutral tag): the module calls `FS.GunsightShamanShocks` Build / Seat / OnShow / OnHide when that table exists, and tells the section where the Fire totem is through `section.SetFire(up, headY)` (`up` = the Fire totem stands and is not FAR; `headY` = the Fire head's centre in image px from the rect's top, still sent and now ignored, the flame disc does not ride the head; called when either changed and once after the section's OnShow). A set drop (Call of the Elements, Ancestors, Spirits) stamps every element whose multi-cast slot for that set holds a spell (action id `(barIndex - 1) * 12 + (set - 1) * 4 + slot`, `HasAction` / `GetActionInfo` plain; numbers from `DEFS` through the assigned spell, plus the drop position), replacing a standing totem's numbers; an element with an empty set slot is untouched. When the bar index or `HasAction` is unavailable it falls back to stamping only the slots not up. The pole art that a solid texture cannot draw (block with its dark line, dashed mold, dashed DROP / FAR head outline) is baked by `tools/assets/generate_totem_pole.py`. The IMBUE and SHIELD chips are on the Shaman buff tab on the Console top edge (`Modules/ActionBars/BuffTab.lua`, data in `ShamanBuffs.lua`, always visible, no target needed). `gunsightshaman-harness.py` pins the poles, `shamantotems-harness.py` the data, `buffbar-harness.py` the tab.

- Which module each area holds is `gunsight.target.upper` / `.lower` (`Gunsight.GetArea` / `SetArea`). `SetArea` swaps with the other area when it already shows the picked module (Target Debuffs H and V are one family); `Gunsight.OnAreaChanged` fires once per `SetArea` (the swapped key included) and once per key for a profile switch or direct config write, so listeners must recompute from state.
- The Gunsight master switch (`gunsight.enabled`) applies live to what was built: `Gunsight.IsEnabled()` is the login snapshot (what exists), `IsActive()` / `OnActiveChanged(fn)` follow the switch, and the root (parent of every piece) is shown or hidden, by alpha only in combat with the real Show or Hide owed to PLAYER_REGEN_ENABLED. `GunsightTape.lua` listens and hands the casts to Stack A (`FS.CastBars.ClearView`) or takes them back (`SetView`); a new module that draws casts or owns a listener must do the same from `OnActiveChanged`. `NeedsReload()` names what cannot be live (a Gunsight never built, the classic combat HUD never drawn) for the config row. In combat the root only fades, so an insecure OnEnter, OnClick or tooltip under it must return early while `IsActive()` is false (the secure target of target button and the secure target menu button, both in `GunsightTags.lua`, are the accepted exceptions). The party frames are not a Gunsight piece and the master switch never touches them: `FS.PartyFrames` (`IsShown`, `SetShown`, `OnShownChanged`, saved at `FS.PartyFrames.CONFIG_KEY`) owns their switch, and the Console's party key (`ConsoleKeys.lua`) stays drawn with the HUD off as the tab's one key. Only the HUD keys hide from `OnActiveChanged`.
- Target menu: `GunsightTags.lua`'s second secure button (`FS.GunsightTags.menu`) covers the target box and opens the unit menu on a right click (`unit = target`, `*type2 = togglemenu`, `RightButtonUp` only; left and middle fall through via `SetPassThroughButtons`, read back with `ShouldButtonPassThrough`, else the mouse stays off and one line is logged). It hangs from the box ANCHOR with the box frame's offsets, never from the box frame (which moves in combat), is built and reseated out of combat only (`box.onGrow`, rescale, `PLAYER_REGEN_ENABLED`), and is hidden with no target by `RegisterUnitWatch`; never call Show or Hide on it. Accepted limits: (1) while there is a target, a right-button press that starts over the box opens the menu and does not start a camera turn (left and middle pass through; the right button is the menu); (2) like the master-off exception above and the target of target, the mouse cannot be switched in combat (`EnableMouse` on a secure frame is blocked), so turning the Target piece off mid fight leaves the invisible box taking right clicks until `PLAYER_REGEN_ENABLED`, and a piece turned on mid fight waits the same way.

## New Gunsight module: show/hide checklist
Everything on the target side hides with no target (player, live, Shaman: an IMBUE chip floated alone with no target; self buff reminders belong on the player side, not here). Before a module is done:
- Name its visibility contract: target (hides with no target, the default for `class`), dots (`FS.TargetTakesDots`), or always (only the player side, never the target side).
- A `class` module needs no gating code of its own; do not add a `showWithoutTarget` style exception without the player's recorded approval.
- Every frame, texture and font string hangs under the host the registry hands `build(host)`, never `UIParent` or `Gunsight.root`, so the host's hide takes it along.
- `onHide` stops the OnUpdate and every event the module registered; `onShow` restarts them and re-reads state (the spellbook, auras and weapons may have changed while hidden).
- Anything that happens while hidden and cannot be re-read later (a cast, a learned id) needs a listener that stays on through `onHide` and only records data (a Shaman imbue cast with no target is the example; that data model now lives in `ShamanBuffs.lua` because a self buff reminder belongs on the player side); everything else is re-read in `onShow`.
- `onShow` runs inside the `PLAYER_TARGET_CHANGED` dispatch, before per-target reads (combo points, `UnitPower`) reflect the new target: re-read them next frame (`RereadNextFrame` in `GunsightClass.lua`).
- A caller that draws something else while the module is on screen asks `AreaOf(id, true)` (nil while the target gate hides the host), and re-renders from `OnAreaChanged`, which also fires on the gate edge (CombatHud's Warlock shard count under the cast bar). The callback gets `reason`: `"gate"` when only a class host's target gate flipped, nil otherwise (registration, assignment, profile switch); a listener that only cares about assignments skips `"gate"` (TargetDebuffs does, and CombatHud skips it unless the player is a Warlock).
- Plain frames only (no secure button under a host), so show, hide and `SetParent` stay legal in combat.
- Walk these states: no target, dead target, friendly target, hostile target, in combat, after `/reload` with no target, the Console key off, and the Gunsight HUD off in `/fsconfig` (`IsActive()` false). The master switch hides the root and does NOT fire `onHide`: a module keeps its events while the root is hidden, so it must stay cheap and must not draw outside the root.
- The harness has a case that clears the target and asserts the host and module are not visible and `onHide` fired, then sets one and asserts `onShow` (see `gunsightareas-harness.py`, `a_class_module_hides_with_no_target_and_follows_it_with_its_hooks`; a module's own harness adds a real-areas case like `gunsightshaman-harness.py`).

## Dependencies
- Depends on: `FS.HudSpells`, `FS.HudProfiles`, `FS.Config` (GunsightBoxes, Gunsight areas)
- Depended on by: CombatHud.lua, GunsightSeals.lua (the pushed state: `seal`, `judgeAt`, `judged`; `HudSpells.jd.cooldown`), GunsightDots.lua, GunsightFrame.lua
- Buff reminders in combat (Gunsight view): aura reads are blocked, so a tile cannot ask whether a buff is up. `CombatHud.lua` builds, out of combat, one AuraContainer slot per tracked aura buff on unit `player` (the container is invisible at alpha 0, the slot draws nothing) and uses the slot only as the engine's "aura present" flag: `slot:IsShown()` is a SECRET boolean in combat, and `FS.FrameHelpers.AuraFlag.Drive(tile.holder, slot, 0, 1)` hands it straight to `SetAlphaFromBoolean`, so the tile is dark while the buff is up and shown while it is not. Never test, compare, print or store that value: the only use is passing `slot:IsShown()` directly as the setter's first argument. The alpha is resolved when the setter runs, so a driver must call `Drive` again when the aura may have changed (render, `UNIT_AURA`, a throttled OnUpdate on `ui.flagDriver`); a plain `SetAlpha` resets it. A tile is engine driven only when its buff was missing at the pull (held verdict) or an aura was removed this fight (`ui.flagGate`, opened by `AuraFlag.MayHaveRemoved` on the `UNIT_AURA` payload, whose lists are plain nil or secret tables in combat so only their presence is told), and only if the slot's plain out of combat flag agreed with the aura read (`AuraFlag.Agrees`, `tile.flagBad`). Without any of that the held verdict alone shows at plain alpha 1. Stack A keeps its older visible cover slot. The Shaman buff tab (`BuffTab.lua`) has its own copy of the engine state code and is not on this path.
