# Config

The `/fsconfig` window: a grouped nav, a well with sub tabs and folding sections, built from `FS.ConfigWindow.UI` builders. Constants come from the prototype (`mockups/config-window-2026-11-25.html`, SPEC const); everything drawn here is pending owner review.

## Key Files
- `ConfigSpec.lua` -- every size by its prototype name (`CW.Spec`), `Derive(w, h)` for what follows the window size, `Snap`, the colour map. Nothing else types a size.
- `ConfigWindow.lua` -- chrome, grouped nav, tab strip, flow layout, scroll, resize grip, the row registry, events and every extension point
- `ConfigBuilders.lua` -- the `UI.*` builders (Section, Toggle, Segmented, Slider, Dropdown, Button, Acts, Info, Note, Swatch, Text, Order, Confirm, Prompt) and `FS.ClassModuleHelp`
- `ConfigPage*.lua` -- one file per page (Unit Frames, Party, Raid, Pet, Plates, Screen = Action bars, Bags (one switch) and the note pages (Cast bars, Buffs and debuffs), Addon tabs, Class modules, Gunsight, Chat, Minimap, Tracker, Data bar, Skins, Roles, Profiles, Help, Bars)
- `ConfigPageBars.lua` -- the shared frame Style tab: `Bars.SECTIONS` (one table of rows by setting suffix and frames), `Bars.BuildStyleTab(content, { page, tab, frames, header, before, previewTip })`, `Bars.RegisterFrame` for a frame's preview, `Bars.WIRED` for the rows a frame applies (the rest show greyed with a reason). Settings are `bars.<frame>.<suffix>` through `FS.FrameStyle`
- `ConfigSearch` -- see Search below. `ConfigShare` -- stub a later ticket fills; uses only the extension points below
- `ConfigFooter.lua` -- Reload UI (a count chip and glow while anything waits; a click only calls `FS.SecureReload.Explain()`, hover covers the button with the secure /click button, never `ReloadUI()`), Reset page (confirm dialog, the shown page's changed keys only), Close, the saved window position (`winX`, `winY` in `ForeverSTUwaveDB.ui`, clamped on screen). Hooks: `CW.Footer` (`Pending`, `PageKeys`, `OpenReset`, `ClampPosition`, `SavePosition`, `RestorePosition`, `Update`, `Look`) and `CW.AddReloadSource(fn)`: fn returns labels or `{ label, line }` for waits that are not a row's `reload` (ConfigModules hands over `MS.PendingKeys()` this way). Harness `tools/configfooter-harness.py`
- `ConfigTargets.lua` / `ConfigFlash.lua` -- hover flash: `CW.Targets` (`PROVIDERS`, `Providers(entry)`, `Resolve(entry)`, `Prefixes()`, `Pages()`) maps a row to the frames it changes (its own `target` opt: a provider name, a function returning frames, or a frame; else the longest key prefix; else its page), returning plain rects `{ left, bottom, width, height }` in UIParent units, never frames. `CW.Flash` (`Enabled`, `Start`, `Show`, `Clear`, `Envelope`, `Overlays`) draws a pooled outline on UIParent 150 ms after a row is hovered; switch `config.flash` in Profiles > Window. A frame not on screen draws nothing and the row's ? says so. Only `UI.Toggle` forwards `target` to the registry; other builders must forward `o.target` before a row can use it. Harness `tools/configflash-harness.py`
- `ConfigModules.lua` -- module power: the nav power buttons and count chip, the off card, the Modules list page and the Profiles `ALL ON` row. The store itself is `Core/ModuleSwitch.lua` (`FS.ModuleSwitch`); this file returns early when it is absent
- `HelpModules.lua` -- the class modules explained: pictures, pins, words and the shared `Layout` (Help page, Gunsight tip, listing)
- `HelpPicturesArt.lua` -- GENERATED by `tools/assets/help_pictures.py`: where each picture sits in `help_pictures.tga`

## Patterns
- A builder takes `(content, opts)`, stacks itself into the tab's flow, binds `key` to `FS.Config` (or `get`/`set`), registers one refresh with `Track` and one row in the registry, and returns its row; `row.control` is the clickable part. Rows are not positioned by the builder: `I.Reflow` lays visible rows out again whenever a `when` predicate flips, a section folds or the window resizes. Never read a row's y at build time.
- Pages are `CW.RegisterCategory{ key, label, group, order, tabs }`; a tab is `{ key, label, build(content) }`. A page with one tab shows no strip. Groups are FRAMES, SCREEN, PANELS, GENERAL. A tab builds lazily on first show.
- `CW.ExtendTab(page, tab, title | { title, tip, fold, two, meta, when }, build(content, section), order)` adds a section to someone else's tab. The tab's own content is order 0; the default is 100; Profiles' Saved data is 1000. Other lanes use this and the registry, never the page files.
- `CW.Open(page, tab, rowKey)`, `CW.On("show" | "hide" | "select" | "jump" | "rowEnter" | "rowLeave" | "change", fn)`, `CW.TabMark(page, tab, "left" | "right" | nil)`, `CW.NavSlot`, `CW.NavRows`, `CW.FooterSlot`, `CW.SearchSlot`, `CW.JumpHighlight`, `CW.PageBody`, `CW.Rows()`, `CW.RowByKey(key, page)` are the hooks. A registry entry is `{ key, label, tip, page, tab, section, row, sub, needs, reason, enabled, reload, min, max, target, when, inverted, nodot, kind }`.
- Sections: `fold = true` starts folded (state in `ForeverSTUwaveDB.ui.folds`, account wide, id `page/tab/Title`); `two = true` pairs rows two to a line; `when` hides the section. Size and fold state live in `ForeverSTUwaveDB.ui`, never in a profile.
- An inverted row (`inverted = true`) shows and writes the opposite of its key: "Show player frame" over `unitFrames.hidePlayer`, so saved data keeps working.
- `needs` / `nl` on a row record what switch it depends on; `enabled()` plus `reason` does the same for a computed condition. The builder dims the row (`fsRowOff`, walked by `I.RowOff`), disables the control and puts "Requires X to be on." first in the ? tip. A Button with `enabled` must give a `reason`.
- Changed markers: `I.EntryChanged` / `I.EntryReset`, `CW.ChangedKeys(page[, tab])`, `CW.ResetKeys(list)`. A row shows a pink dot and a reset glyph when it differs from the default; sections, tab buttons and nav items show counts or dots, painted by `I.UpdateChanged` at the end of `RefreshAll`.
- `UI.Slider` shows its number in an edit box (`row.fsEdit`) with the unit beside it (`row.fsUnit`); `row.fsReadout` keeps the full formatted text, hidden. Enter commits (snapped, clamped; pink flash when it had to move or was not a number), Esc restores, Tab leaves, Up/Down step by one step and Shift by ten. One box has focus at a time (`I.SliderFocused`); a click elsewhere, a click on the window or hiding it releases it.
- `Track(fn)` / `I.TrackState(fn)` file a refresh under the tab being built (`ui.building`). `RefreshAll` runs the shown tab's lists plus the global ones and marks every other built tab `stale`; a hidden window only marks. Never call a control's refresh from outside `RefreshAll`.
- `UI.Order` (the Data bar segment row: label, title box, two arrows, ON / OFF word, switch) carries its own behaviour, so a page supplies data only. `onType(text)` is the live rename (keystrokes only, never a `SetText`); Enter, Tab and a click away keep the title (`setTitle`, run as the box lets go, focus held through `I.SliderFocused`), Esc puts back the title the box had when it was clicked into; `lock()` disables the switch alone; `upHint` / `downHint` word the arrow tips (default Move left, Move right). The arrows are pixel triangles, not text, because the client fonts have no triangle glyphs: `I.NewArrowGlyph(button, "left" | "right")` is one unit wide rect per column, 4 by 8, centred on the button; plain is cyan on the ink fill, hover lights the ring, pressed darkens the fill, disabled is the dim violet glyph on the darkest fill and answers nothing. The Data bar page keeps only what a builder cannot know: its model reads, re-seating the rows in the bar's order after a move (`SeatRows`), and the order's one registry entry on the section header (`I.Register(sec.header, ...)`). Section chevrons and the Dropdown caret are drawn the same way (below).
- Arrows are drawn, never typed: the window's font (Mononoki) has no U+25B8 or U+25BE, and ">" or "v" read as a sign and a letter. `I.NewArrowGlyph(host, "left" | "right" | "up" | "down")` returns `{ textures, direction, width, height, SetColor(color), SetShown(bool) }`: one rect per column (left, right: 4 by 8) or row (up, down: 8 by 4), centred on the host on whole units, so the host's own centre should sit on a unit. A folding section's chevron (`sec.chevron`, an 8 by 8 cell in the gutter left of the content, never further than the page's 8 unit clip) shows the right triangle while folded and the down triangle while open: dim violet (`--dis`) folded and idle, cyan while the header is hovered, nothing while open and idle. Whoever sets `sec.folded` calls `sec.PaintChevron()` (the header click and a search jump do). The Dropdown caret is `b.fsCaret`, a cyan 8 by 4 down triangle in a child cell 8 units from the button's right edge, so the button's disabled dimming takes it along. Harness `tools/configglyph-harness.py`.
- Labels and values only on a row; any explanation goes in the `tip` (a `?` icon tooltip). Player-facing text says "cast bar", never "tape". Every alert gets an off switch.
- Every tab page is a clipped `ScrollFrame` (builders stack into `fsHolder`). Range, wheel, thumb and rail follow the viewport (`ViewH`); `CW.RefreshScroll()` after adding rows to a built page. On a scrolling page the wheel over a `UI.Slider` scrolls the page; Shift adjusts the slider. Popups (dropdown menu, dialog) are parented outside the clip.
- `UI.Toggle` takes an optional `reload` function (master rows): the line it returns shows beside a Reload button, nil hides both.
- `UI.Slider` is built from Theme pieces on a plain Button, not a Blizzard Slider; it drags through an `OnUpdate` that exists only while the mouse is down.
- The Help page is the one exception to "labels only": the commands, then `UI.HelpModules`, class tabs and the module picture (`help_pictures.tga`, NEAREST) with pins and arrows, then the numbered lines. Everything about it lives in `HelpModules.lua`, which `tools/assets/help_pictures.py` also runs to bake the atlas and the CurseForge listing. `UI.HelpModules` must be the last row on its page. New pictures: add a frame to `tools/assets/help_frames.py`, rerun it and `help_pictures.py`.
- Old page names still open: `CW.Open("unitframes")` is the Unit Frames page (alias), so the layout editor and slash command keep working.

- A frame page never writes its own rows: it names its frames and gets the shared sections. A new row goes in `Bars.SECTIONS` once, with `frames` saying where it shows. The preview band draws the real frame code (`FS.UnitFrames.NewPreview`, `FS.RaidFrames.NewStylePreview`, `FS.PartyFrames.NewStylePreview`) and a hovered switch row is turned on in it through `Style.override`.

## Roles page (ConfigPageRoles.lua)
- Four tabs (Tank, Healer, Melee, Ranged) with the same pinned "Your role" bar on each: a real `UI.Segmented` is built into the tab, taken out of the flow (`I.FlowOwner(content).fsFlow`) and seated in a `UI.Band`, so its registry row, refresh and ? tip are the usual ones. It is registered once (the first tab built); the other tabs only draw it. What Auto chose shows in cyan after the ? and the tip adds `Role.Why()`.
- A section's tag (YOUR ROLE cyan, "<ROLE> ONLY" amber) is set in the section header's meta (`sec.SetMeta`) from an `I.Track` function, so a role change retags every section at once. Rows of another role stay editable and keep their values; `FS.Role.Active` is what makes them act only while their role is in use.
- The arrow on the tab of the role in use is `CW.TabMark("role", tab, "left")`, set from an `I.Track` function and cleared (nil) on the other tabs. The window remembers a mark per tab, so it can be set before the strip exists and survives a tab change; a value other than "left" or "right" is reported and ignored. The triangle is drawn from rects (`I.NewArrowGlyph`) in the tab's right padding, cyan, because the client fonts have no triangle glyph.
- A row that cannot act yet is greyed with a reason (`enabled` plus `reason`): Healer "Health text" until the party frames can show the missing amount.
- Harness `tools/role-harness.py` (page checks run over `configwindow-harness.py`'s mock frames; they need `FS_MOCKUPS_DIR` for the prototype).

## Module power
`FS.ModuleSwitch` (`Core/ModuleSwitch.lua`, loaded right after `Config.lua`) holds one on / off switch per part of the addon: sixteen keys (`m.uf` ... `m.skins`) with the prototype's labels and the page each one sits on. Off is stored as `false` in `ForeverSTUwaveDB.modules` (account wide, not a profile, because a module builds before the character's profile is known); on is stored as nothing. Only `m.np` (Nameplates) is `live`; every other switch takes a Reload UI (the secure /click cover, never `ReloadUI()` from addon code).
- Words: `Wanted(key)` is the store now, `On(key)` is the switch as this session loaded it (a live module's follows `Set`), `Pending(key)` is `Wanted ~= On` for a non live module. `On` answers true before ADDON_LOADED and for an unknown key, so never read it at file scope.
- Gate a module with one call: `MS.WhenOn("m.cast", function() Build() MS.MarkBuilt("m.cast") end)` in place of the file scope `Build()`, or `if not MS.On("m.cast") then return end` inside a PLAYER_LOGIN or later handler. `WhenOn` runs the function at this addon's ADDON_LOADED (SavedVariables in, PLAYER_LOGIN not yet fired); a call after that runs at once. A key nobody registered is forwarded as an error and runs anyway, so a typo cannot turn a module off. A gate that throws is forwarded and never stops the next one.
- Saved state is read at run time, never at file scope: the client hands `ForeverSTUwaveDB` (and `FS.Config`'s profile) over at ADDON_LOADED, after every file ran, so a file scope read of a saved global is nil and a `Config.Get` there answers the default. Read in the handler or function that uses it, and re-read at PLAYER_LOGIN or on `Config.OnChange` anything cached from a setting. Do not make the table at file scope either (`ForeverSTUwaveDB = ForeverSTUwaveDB or {}`): the client replaces it and the writes are lost. `tools/moduleswitch-harness.py` row `no_saved_global_or_setting_is_read_while_the_files_load` loads the whole .toc with the table absent and fails on a new file scope read (its short allow list says why each remaining one is harmless).
- Gates: all sixteen are in. `m.cast`, `m.auras`, `m.mini`, `m.track`, `m.bags`, `m.skins` (B5a), `m.ab`, `m.class`, `m.gs`, `m.pet` (B5b), `m.uf`, `m.party`, `m.raid`, `m.np` (B5c), `m.chat` and `m.data` (B5d); `tools/moduleswitch-harness.py` checks that every key is read by a module file and that every module but the live `m.np` calls `MarkBuilt` for it. Shape of every gate: the build runs behind the switch and calls `MS.MarkBuilt(key)`; every API table stays defined when off (functions answer empty or do nothing); nothing dims, hides, reparents or hooks a Blizzard frame while off; dependents ask `MS.Built(key)`. `tools/moduleswitch-harness.py` has a gate world that loads the whole .toc and records every Blizzard call by file.
- File scope registrations of the window skins: `PanelSkins.DeferCombat(fn, key)` and `PanelSkins.WatchAddonLoad(callback, matches, key)` queue a call made at file scope through `WhenOn(key or "m.skins")`, so a skin never runs with the switch off; a caller that is not a skin passes its own `key` (`m.track`, `m.bags`, `m.mini`). `PanelSkins.WhenSkinsOn(fn, key)` does the same for other file scope skin effects (listeners, hooks, direct skin calls). A call made after ADDON_LOADED (a window opens, combat ends) is never gated. A file whose harness world does not load PanelSkins keeps a six line local `WhenSkinsOn`.
- Class modules page: its tabs show one note each (built from `m.gs`) in place of their rows while the Gunsight HUD is off for this session; the note follows the switch turned back on before the reload.
- A module that needs another: `MS.Register({ key = "m.party", requires = { "m.uf" } })` once. Turning the required one off asks first (`UI.Confirm` naming the dependents) and turns them off with it; turning one on pulls its requirements on (`SetWithDeps`). `m.class` requires `m.ab` (every addon tab stands on the Console), registered in `ClassShoulder.lua`. `On(key)` does not look at `requires`, so a store that has the required switch off and the dependent on (a hand edit or a profile import) builds the dependent empty; write through `SetWithDeps`.
- A live module (Nameplates) listens with `MS.OnChange("m.np", function(on, old, key) ... end)`; the config window repaints from `MS.OnAnyChange(fn(key, new, old))`.
- For other lanes: `MS.PendingCount()` / `MS.PendingKeys()` feed the footer's reload line, every module switch row carries `entry.reload()` (returns "Takes a Reload UI." while pending), `MS.Snapshot()` is `{ [key] = on }` for an export, `MS.Set(key, on)` returns `true` or `false, reason`, `MS.IsWritable()` is false before load, without saved settings or while `Config.IsReadOnly()`.
- Nav: every module page's nav row gets a power button (`nav.fsPower`, `fsKey`) on the right with the `?` help mark moved left of it. Off mutes the row label (the label's `SetTextColor` is shadowed on the instance because the nav recolours on every select). The "Modules" nav row shows a pink count chip while a reload is pending.
- Off card: `ForeverSTUwaveConfigOffCard` covers the well below the tab strip when the shown page's module is not `Wanted`; the tab page is hidden underneath (and kept hidden through an `OnShow` hook) so neither hover nor wheel reaches it. Its big power button turns the module on. It is drawn when the switch is off, not when the module has stopped, so a non live module still running this session shows the card until the reload. A module can add one thing to its card: a `?` after the second line carries the sentence from `OFF_NOTES` in `ConfigModules.lua` (only `m.pet` today: the game's own pet unit frame comes back while the pet bar is off). Cards with no note show no `?`.
- The power glyph is drawn from rect runs on a 12 grid (nav) and a 16 grid at 2x (card) because there is no power texture; `NewGlyph` in `ConfigModules.lua` owns them. Colours: on pink, off `DIS`, hover cyan, pressed mixed with white, 40 percent alpha when not writable.
- `tools/moduleswitch-harness.py` drives the store and the UI over `configwindow-harness.py`'s mock frames: prototype parity for keys and labels, load timing, requires, read-only, the card, the chip, the confirm, `ALL ON`, and a check that the toc loads the store before the pages that gate on it.

## Search (ConfigSearch.lua)
- The box sits in `CW.SearchSlot()`; the index is `CW.Rows()` (only built tabs record rows), so the first focus builds every unbuilt tab hidden, one per frame, never in combat and never while the window is shut (`CW.BuildTabHidden(page, tab)` is used when ConfigWindow exposes it, else the tab is opened and the old one reopened inside the same frame). Typing never builds frames; a query reads only the index.
- Ranking: label prefix, label substring, section title, tip, loose letters of the label (3 or more); spaces and case ignored; ties go to the shorter label. `CW.Search.Run(text, changedOnly)` returns `{ item, score }`, `item.label` / `item.entry`.
- A row hidden by a `when` is still indexed. `CW.SearchGate{ id, page, tab?, values(), set(value), with(value, check) }` names the picker that shows it: the result's breadcrumb ends in the picker value and a jump calls `set` first. Built in: the Addon tabs class strip (`tabs.cls`) and the Unit Frames Style frame picker (`bars.module`). A hidden row no gate can show is dimmed HIDDEN and the jump stops at its section.
- `CW.JumpHighlight(entry)` unfolds the row's section, scrolls the row in and draws the cyan 1 pixel outline (fades in over 0.3 s, held until the next click, a new search or a page or tab pick). `CW.Open` calls it for every jump, so any caller (the layout editor) gets it.
- Harness: `tools/configsearch-harness.py`.
- `CW.BuildTabHidden(page, tab)` (ConfigWindow.lua) builds one unopened tab with no Select, no "select" event, no scroll reset and no refresh; the page stays hidden and is marked stale. Search uses it for the pre build; a later `CW.Open` shows it normally.
