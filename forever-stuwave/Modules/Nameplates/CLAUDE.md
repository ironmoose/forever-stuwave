# Nameplates

STUwave's own plates drawn over the game's, the combo pips under the target's plate, and the role threat view. The Nameplates page (`Config/ConfigPagePlates.lua`) and the Roles page (`Config/ConfigPageRoles.lua`) read the settings tables here; nothing in this folder reads a config page.

## Key Files
- `Nameplates.lua` -- the plates themselves, exported as `FS.Nameplates` (`Plates`). Loads before `Theme.lua` and reads theme exports at runtime. It sits near the parse gate's file scope local limit (183, the gate fails at 190): add to the `Plates` table, never a new file scope local.
- `NameplateCombo.lua` -- five combo pips under the target's plate (Rogue, and a Druid in Cat Form); the pips sit below the cast bar slot, which follows `plates.castH`.
- `PlateThreat.lua` -- `FS.PlateThreat`, the threat view for the role in use (colours, Aggro % or Lead text, alerts, range dim). Loads after `Core/Role.lua`; without `FS.Role` it does nothing.

## Settings (Nameplates.lua)
- `Plates.SETTINGS` is one table of `{ key, default, min, max, step | options }` for width, health, power and cast bar heights, name size, level, health text, quest marker, auras, raid marker and friendly plates (`plates.*`); `Plates.S` is the values in use, read once at login and on every change (`Plates.ReadSettings`), so plate code never reads the config on a hot path. A bad stored value reads as the default or the end of its range.
- `Plates.ApplySettings()` diffs `S` and applies what moved to the plates that are up and to the pooled ones (a pooled plate is laid out there, so its next acquire needs nothing). It touches only this file's own frames, so it is safe in combat.
- `Plates.GEOMETRY` and `Plates.PALETTE` are what the page's preview band draws from; change a measure there and the preview follows.
- Power height 0 closes the strip and the plate shrinks; cast height 0 never shows the bar.
- Friendly plates: Same as enemy, Smaller (the root scales to `GEOMETRY.SMALL_SCALE` around its centre), Off (no STUwave plate is built, the game's own stays hidden). A friendly is a unit the player cannot attack and that is a friend; a secret answer counts as not friendly. A duel or flag change refits the plate (`Plates.Refit`).
- Health text is written by `SetFormattedText` only; the percent is `UnitHealthPercent(unit, false, CurveConstants.ScaleTo100)`, feature detected. Nothing here compares a secret.
- `nameplates.enabled` (`Plates.SETTING`, the Nameplates page row) is now a view of the `m.np` switch, see Module power below; off leaves the game's plates as they are.

## Module power
`m.np` (Nameplates) is the one live module (`Core/ModuleSwitch.lua`, see `Modules/Config/CLAUDE.md` "Module power"): switching it off and on applies at once, without a reload.
- Off registers nothing. The file loads before ModuleSwitch and Config (.toc), so it cannot ask the gate at file scope: it listens only for its own ADDON_LOADED, and `Plates.Boot` then calls `MS.WhenOn("m.np", Plates.Start)` (the events and `Plates.on`) and `MS.OnChange("m.np", ...)`. `Plates.RegisterEvents` and `Plates.UnregisterEvents` own the whole event list (`Plates.EVENTS`, `CAST_EVENTS`, and UNIT_AURA for the fallback row); no event is registered at file scope any more except ADDON_LOADED, and no plate event is delivered while the module is off. `Plates.on` starts false and the gate turns it on.
- Switching off (`ApplyPlatesSetting`) releases every root, gives each stock plate its UnitFrame back with a plain Show (the Show hook reads `Plates.on` and goes inert), forgets `FS.platesByUnit` and unregisters the events. Switching on registers the events, reads the plates that are up from the client (`Plates.Discover`, `C_NamePlate.GetNamePlates`, feature detected, because nothing tracked them while off), runs the once per session set up (`Plates.EnterWorld`: saved settings, Questie and aura hooks, the target mark) and builds a root on each plate. Nothing here is protected, so it works in combat.
- The module switch is kept per profile (`profile.modules`, see `Modules/Config/CLAUDE.md` "Module power"): switching profile switches the plates live (`MS.OnChange("m.np")` fires for a profile change that moves it, so `ApplyPlatesSetting` builds or releases the roots, and a profile change never counts as a wait for a reload). The saved `nameplates.enabled` is the switch's older home. Config.lua reads it once at load (`MigrateModules`, marked by `ForeverSTUwaveDB.nameplatesSwitchMigrated`): every profile that saved it off gets `m.np` off in its own `modules`. After that the key is a view of the module switch of the profile in use: the module switch writes it (`Plates.MirrorSwitch`, so the page row shows what the plates do) and a change of the key writes the module switch (`Plates.OnKeyChange`, the page row); while a profile change runs (`Config.Reapplying()`) the key is put back to the switch instead, so another profile's stale copy never turns the plates off or on against its module switch. The key stays for one release, then the page row can go. The key is registered at ADDON_LOADED so the row works with the module off.
- The `Plates` table still holds everything the file exports; the file is at the parse gate's file scope local limit (183 of 190), so nothing here added a local.
- `PlateThreat.lua` is not gated: its frame listens for plate events of its own and works through `FS.framesByUnit`, which is empty while the module is off.
- Harnesses: `tools/nameplate-auras-harness.py` delivers an event only to a frame that has it registered (its `fire`) and fires ADDON_LOADED in `boot()`; `tools/moduleswitch-harness.py` has the live on and off rows, the migration into the profiles, the profile switch row and the off world that checks no plate event is registered.

## Provider hooks (for PlateThreat, or any later view)
- `Plates.SetColorProvider(fn)`: `fn(unit)` answers a colour table (three plain numbers, alpha ignored) or nil to keep the plate's own fill. Asked whenever a plate's fill is worked out, on the threat events, and once for every plate that is up when the provider is set. A tap denied plate keeps its grey. Hand back the same table each time: the plate skips a fill it already wears by table identity.
- `Plates.SetTextProvider(fn)`: `fn(unit)` answers a string (a secret string is fine, it goes to `SetText`) and optionally a colour table for the small threat text inside the health bar. It may instead answer a number (a secret one is fine) with a colour or nil and a format string such as `"%.0f%%"` as the third answer: the field formats it itself with `SetFormattedText`, the call the health text makes with a secret percent. A number with no format, or a call that throws, hides it, like anything else.
- No provider is the default (today's look). `nil` removes one. A provider that throws is swallowed and logged once (`plate_color_provider`, `plate_text_provider`); the plate keeps its own look.

## Role threat (PlateThreat.lua)
- `PT.Apply()` installs or removes the two providers for the role in use and the settings, and starts or stops the range check. It runs on login, on entering the world, on `FS.Role.OnChange` and on every `FS.Role.KEYS` setting change, so switching the role changes the plates at once. Only Tank, Melee and Ranged colour plates; only Tank gets the text provider.
- Role gating: every setting is read through `FS.Role` and acts only while its role is the one in use (`Role.Active`); the settings of the other roles keep their values and do nothing. The same switches read as the default when the value is secret or bad.
- Colours: tank on me cyan, slipping amber, not on me pink; melee and ranged on me pink, close amber (share at or above `<role>.pct`, else status 1 when the share is secret), safe cyan. The three colours are `PT.PALETTE`; `PT.SWATCHES` is what the page shows under "Colours".
- Alerts (`ALERTS`, each with its own switch; the sound has another): tank "lost aggro" (was mine, now other, sound `RAID_WARNING`), healer "a mob turns to me" (was other, now mine, sound `TELL_MESSAGE`), melee and ranged "warn" (was safe, now close, no sound). A mob alerts at most once per `TUNING.ALERT_GAP`; a state is read before it can change, so a mob first seen already on someone does not alert. The flash is a texture over the health bar (`root.threatFlash`) fading over `TUNING.FLASH_TIME`.
- Range dim: the target plate's health bar at `TUNING.DIM_ALPHA` out of range, checked every `TUNING.RANGE_EVERY` seconds. Melee uses the class's melee spell and the duel distance (`TUNING.NEAR_INTERACT`) together, ranged the class's spell; a secret answer goes to `SetAlphaFromBoolean`. The bar is put back to 1 when the role, the setting, the target or the plate changes.
- Secret text: a secret percent cannot be formatted by Lua, so `PercentAnswer` hands it to the plate as the number with the format `%.0f%%` and the plate's own text field formats it (`SetFormattedText`, see Provider hooks); when the client will not, the text stays hidden. A plain number is rounded and formatted by Lua. Neither gets a sign: Lead is the game's own number, shown the way its target frame shows it. (An earlier version round tripped the secret through a hidden scratch font string and `GetText`; that path never ran on the client, and Lead on a plate is secret there, see below.)
- Threat text is shown only for a mob that lists the player (`ReadThreat`'s fifth answer, `listed`): the detailed read returns nothing and `UnitThreatSituation` returns plain nil for a mob that does not, while `UnitThreatPercentageOfLead` answers 0 there (read through `"target"`, the recon; a plate's answer is secret, so its value is not seen), so without the check every idle plate would read `0%`. A state that cannot be read (secret, missing, throws) is not "not listed" and the text shows.
- Every threat read is feature detected, wrapped in `pcall` and checked with `FS.IsSecret` before a compare; a read that cannot be trusted answers nil and nil leaves the plate with its own colour.
- What the client gives (`ForeverSTUwaveDB.recon.threat`, 2026-09-25 beta; `debug/priest-probe-dump-2026-10-09-run2.txt`; the SecretPredicates notes): the threat STATE (`UnitThreatSituation`) is plain for a nameplate token and is nil for a mob that does not list the player; the threat VALUES are plain for `"target"` (`UnitDetailedThreatSituation` 3, 100, 255 while tanking solo; Lead 0 off the list) and `UnitThreatPercentageOfLead` is secret for a nameplate token (the recon, the Forever forum thread of 2026-10-06 and ThreatHelperForever's notes say the same of the detailed percents), so a plate's Lead takes the secret path and the colours come from the state. Not measured here: what Lead reads for a lone tank (other players report it sits at 100 while you hold the mob and falls toward 0 as someone closes in, which is not "how far ahead"); `docs/TESTING.md` asks for it.
